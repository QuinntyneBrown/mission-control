Administrator-only. Focus starts in the password field. After the change, Ada's old password stops working and tokens issued before it are refused on their next request. Success returns to the account with the toast "Password replaced: Ada Okafor's current sessions will end."

Allowed for every account, including the designated administrator; setup never resets it. Replacing your own password signs you out: on success the dialog opens the sign-in page with the "You've signed out" notice and then ends the session, so you sign in with the new password.

Opens from Replace password. The dialog reads the account first for its name, email, and version: New password and Replace password stay disabled until it arrives. Whether it's your own account is known at once, so the title already says so when it is. Cancel closes without sending anything. Screen readers hear "Loading account…"; focus moves to New password once the account arrives. A read that answers 404 closes the dialog: from the account's page, that page shows Account not found; from the list, the list reloads and announces that the account wasn't found.

The read failed, so New password and Replace password stay disabled and nothing was changed. Try again repeats the read. This read answered 500, so the reference ID matches the server's diagnostic record; a read that got no response shows "Check your connection and try again." without a reference ID. The alert is announced and focus moves to Try again; Cancel closes without sending anything.

Only length is checked: 12–128 characters, each bound with its own field message, "Use at least 12 characters." or "Use 128 characters or fewer." Spaces count and nothing is trimmed. The input has no maxlength, so a longer pasted password is reported instead of silently cut. The entered value is kept so it can be corrected. The one field error, whether found before sending or returned by the API as a 400, moves focus to New password, which reads its error through aria-describedby; there is no Retry or reference ID.

The button shows progress and ignores repeat clicks. Focus stays on the busy Replacing… button; Cancel and Close wait for the result.

The API answered 500, or 503 because it was busy, so nothing changed and the old password still works. The new password stays in the field, and Replace password tries again; the reference ID matches the server's diagnostic record. The alert is announced and focus stays on Replace password. A request that gets no response may have been applied, so this presentation reads "We couldn't confirm whether the password was replaced" instead, with no reference ID and no claim that the old password still works. The dialog first re-reads the account, with Replace password disabled, so focus moves to the alert; replacing again with the same password is then safe and carries the latest version. For your own password, a replacement that did go through ends your session on that read, and sign-in opens with "Your session ended while a save was in progress". The page behind rereads the account at once while the dialog stays open, so Cancel just closes. If the API answers 403 because you're no longer an administrator, the dialog closes without saving and the access-denied page replaces the account page.

The account changed after the dialog opened, for example another administrator replaced this password, so the API answered 409 and nothing changed. The new password stays in the field and the latest account version is read once. Nothing is resubmitted until Replace password is chosen again. The alert is announced, the dialog's description now points to that explanation, and focus stays on Replace password. When this answers a repeat after a replacement that got no response, the explanation leaves out "The password wasn't replaced", because the first request may be the change it reports.
