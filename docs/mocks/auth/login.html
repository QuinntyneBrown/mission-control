There is no registration, password reset, or "remember me": accounts are provisioned by an administrator and the session lives in memory only. Success opens Home (or the requested page) in place of this page in the browser history, so Back doesn't return to the sign-in form; this address opened while signed in goes straight to Home.

Client-side checks run on submit. With two problems, focus moves to the error summary, and each item links to its field; a single problem, or a server 400 naming one field, moves focus to that field, which reads its error. The email is kept; the password is never trimmed.

The button shows progress and ignores repeat clicks, so only one request is sent.

Unknown email, wrong password, inactive account, and a lead contact without an account all show this same message. The password field is cleared; the email is kept.

After five failed attempts for an email within 15 minutes, sign-in pauses for 15 minutes. The time shown comes from the 429 response's retry timing, the remaining pause, so a later attempt shows less time left. Unknown emails are throttled the same way, so the message never confirms that an account exists.

Shown after Sign out, and after you replace your own password, which signs you out so you can sign in with the new one. The session ends as this page opens: the token and capability summary are cleared from memory, and no contact or work data stays on screen.

Shown after the 30-minute token expires, after a reload, or when the API answers 401 because the account was deactivated or its password was replaced (credential version changed). A role change doesn't end the session: the API answers 403 only to what the new role can't do, and that page or dialog explains it. No contact or work data is shown until sign-in succeeds. A card move, reorder, status change, or other change made outside a form that was still waiting for its answer also ends here: after sign-in its page reads the saved state again, which shows whether the change was made.

Shown when the session ended while a form had unsaved input that was never saved, including a save the API refused with 401. Nothing is reported as saved.

Shown when the session ended (expiry, or a 401 on another request) while a form or dialog's save was still waiting for its answer, or after a save that got no answer and wasn't confirmed since. Ending the session cancels the request in the browser but can't undo it on the server, so the save may or may not have been made. Nothing is reported as saved or as lost. A card move, reorder, status change, or other change made outside a form shows the session-ended message instead.

Opened from a protected link while signed out. The message does not name the record; after sign-in the requested page opens if the account can see it.

Unexpected server failure. The reference ID matches the server's diagnostic record and can be copied for support. The email and password are kept, so Sign in tries again. The alert is announced; focus stays on Sign in.

The sign-in request got no response, for example because the connection dropped. No answer arrived, so there is no reference ID and no session. The email and password are kept, and Sign in tries again only when pressed; nothing retries by itself. The alert is announced; focus stays on Sign in. The application's offline banner belongs to signed-in pages, so it doesn't appear here.
