The project header and tabs stay pinned while the tab content scrolls; on phones only the tabs stay pinned.

Only unfinished stories that aren't already in a planned or active sprint can be added. Adding to the active sprint is a scope change recorded in its history with the person and time. Done stories show the option disabled with the reason.

Kanban projects keep the same priority order but have no sprints, so rows show no sprint information and no Add to sprint.

This project switched from Scrum to Kanban with its sprints kept. Sprint membership is read-only and adding to a sprint is disabled until the project returns to Scrum.

Collaborators can reorder the backlog and add stories to sprints. Project settings are administrator-only, so Project actions is absent.

Shown with a larger dataset: 350 stories, 25 per page, so this is page 2 of 14. Ranks are absolute across pages. Move up on rank 26 moves the story to rank 25 on page 1 and is announced, for example "Moved Team size limits shown at sign-up to position 25 of 350, on page 1"; Move down on rank 50 does the same toward page 3. Dragging stays within the visible page; Move to position… reaches any rank from 1 to 350. Totals count every story, not just this page. Only page 2 is drawn, so the other page links stay here.

A new Scrum project with no stories and no sprints yet. Both roles can add work, so the action is offered to collaborators too. Once stories exist they can be prioritized here and added to a sprint from each row's menu.
